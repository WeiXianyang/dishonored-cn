# 游戏汉化防过修工作流设计

日期：2026-08-07

## 为什么增加 Phase 4.5

原流程能检查占位符、格式、ID 覆盖和低置信度，但仍允许同一个 Agent 同时发现问题、改写译文并为自己的修改背书。术语回溯二审提供了量化证据：1,207 条术语风险结果中有 416 条被第二轮改变，187 条恢复天邈原译。这说明错误修改同样可能带着高置信度出现，不能只复核 `uncertain`。

当前候选共 6,352 条修补，其中：

- 1,012 条玩家相关修补已经通过独立术语二审；
- 89 条来自 `DishonoredEditor.int`，正常零售版不会触发，确定性回退；
- 剩余 5,251 条进入 Phase 4.5 反方二审。

## 统一裁决门

核心模块是 `tools/release_gate.py`，对外提供一组小而完整的动作：

1. `prepare`：冻结候选哈希，按风险分队并补齐本地证据；
2. `attach-research`：把 Wiki、官方资料、游戏脚本或实机证据注入条目；
3. `prepare-repairs`：把“原译和候选都不可发布”的项恢复到原译起点，单独准备修复提案，并一次生成可去重的多源研究队列；
4. `prepare-rereview`：将新提案重新包装成隐藏理由的反方二审输入；
5. `merge-round`：只用通过二审的新候选替换旧候选，并保留整条决策链；
6. `finalize`：验证裁决并默认回退未解决候选；
7. `prepare-consistency`：把同英文、同版本中因修改产生的目标译文分歧压缩成组级复核语料；
8. `merge-consistency`：只允许有语境证据的例外或完整回退本组已改行，不允许现场写新译文；
9. `verify`：拒绝任何未经发布门复核的修补或未裁决一致性冲突。

复杂性集中在这个模块里，调用者不需要分别理解风险算法、单写入规则、作用域排除、默认回退、覆盖检查和审计清单。

## 单写入规则

反方 Agent 只能作三种裁决：

- 接受当前候选；
- 完整回退天邈原译；
- 请求多源研究或重新提案。

二审不得现场写第三版译文。若原译确有硬错而候选改得太多，条目进入重新提案；新候选必须从头再过一次反方二审。该规则同时由 prompt、批次硬校验和最终合并三层执行；合并层以“当前被复核的候选”为唯一真值，防止修复轮通过后又误用旧候选。

为了降低锚定，反方 Agent 看不到第一轮理由和置信度，只能看到英文、天邈原译、候选、风险信号、任务定位、本地邻文和独立证据。

## 多源求证能力

证据优先级：

1. 本条英文、本地同场景对白、相同英文实例和资源路径；
2. 可定位的游戏脚本、对象绑定、实机截图或触发录像；
3. 用户指定的 Dishonored Wiki；
4. Arkane、Bethesda、平台官方博客、手册等资料；
5. 其他可靠一手资料或完整语境攻略；
6. 一般词典和语言直觉。

Wiki 查询命中只算证据，不自动成为中文结论。无结果不能当作反证。需要外部事实时，Agent 用 `[WIKI_LOOKUP: 精确实体]` 生成查询；`phase3_wiki_queue.py`、`phase3_fandom_research.py` 和 `release_gate.py attach-research` 组成可缓存、可追溯的研究适配器。Wiki 不足时由编排层继续查询官方资料和游戏内容。

每条研究记录必须包含问题、状态、来源 URL 或本地资源路径、短证据、来源等级和从证据到本条翻译的推论。原始证据与最终裁决分开保存；`direct_evidence` 若没有可定位来源和实际证据摘要，会被代码硬拒绝。

## 风险分层

风险只决定处理顺序，不能代替全覆盖二审：

- `critical`：否定、情态、数量、方向、参与者或运行时格式发生变化；
- `high`：大幅改写、专名、头衔、对象类型或外部事实；
- `medium`：对白敏感或中等幅度语义修改；
- `low`：没有命中上述信号的小改。

当前真实队列：critical 1,822、high 2,652、medium 714、low 63。

批次同时支持条目数上限和 `--max-batch-chars` 软上限。长教程、大型研究上下文和组级一致性样本使用字符上限拆批，避免固定 20 条在极端情况下形成过大输入。默认值 0 保持旧运行缓存兼容，新的研究/重审轮显式启用。

2026-08-07 首次全量运行在 ChatGPT/Codex 额度用尽前完成 critical 747/1,822 和 high 860/2,652；已完成的 1,607 条经 ID 顺序、输入哈希、配置哈希和当前硬规则复验为 0 错误。额度用尽被分类为“不可立即恢复”，会设置全局停止信号，避免并发队列对同一明确额度错误反复发起请求。既有批次保留原子缓存，额度恢复后从原目录重跑即可复验缓存并继续。

## 错误疫苗库

`research/localization_regression_cases.json` 保存已经发现和人工构造的典型错误。`tools/release_gate_regression.py` 可生成真实模型输入并验收输出。

首版 13 条覆盖：

- `Regent's Safe` 污染 `Safe Room`；
- `Distillery` 的城区/建筑混淆；
- 否定、可能性、方向、主客体和数量改变；
- 普通所有格被物品术语误锁；
- `Wedding Band` 物件类型错误；
- 纯风格重写；
- 原译与候选都不可靠；
- 两条中文社区反馈的已知真错。

当前真实 Agent 验收为 13/13 PASS。以后每发现一种新问题，必须同时加入具体回归条目、通用风险标签和至少一个故意破坏的候选。

## 发布硬门槛

只有同时满足以下条件，Phase 5 才能生成候选包：

- 所有玩家相关语义修补具备独立裁决；
- 未解决条目为 0，或明确回退并排除；
- 错误疫苗 critical 检出率 100%；
- 占位符、变量、标签、换行、编码和术语作用域错误为 0；
- 重复英文、同实体和跨 DLC 一致性差异均有裁决或例外；
- 分层抽检中的错误修改率不超过 1%；
- 成品覆盖和来源哈希可重现。

Phase 5 只构建隔离候选包；安装、卸载、恢复以及本体和各 DLC 的界面/字幕/任务抽测通过后，才进入发布。

## 可复用沉淀

通用方法已安装为个人 Codex 技能：

`C:\Users\wxy\.codex\skills\localize-games-safely`

技能包含通用流程、研究证据协议、裁决契约、风险分级、回归与发布门禁。Dishonored 专有译名、路径、哈希和 Wiki 结论只保留在本仓库，防止项目知识错误外溢到其他游戏。
